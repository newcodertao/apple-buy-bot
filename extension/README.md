# 当前标签页扩展

这个 Manifest V3 扩展把你手动选择的购物标签页连接到本机购买助手，复用该浏览器里已经登录的会话。商品选择、预算核验、加购恢复和订单保护继续由项目现有的 Runtime、Engine 与平台适配器执行。

范围只有淘宝、京东、Apple 中国大陆。天猫没有接入此扩展。扩展连接成功不代表平台登录有效，更不代表真实结算流程已经通过验收。

## 安装与连接

1. 使用 Chrome 125 或更新版本，或支持相同扩展接口的新版 Edge。无需降级浏览器，也无需复制用户资料。
2. 在 Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。启用“开发者模式”，点击“加载已解压的扩展程序”，选择仓库里的 `extension` 文件夹。
3. 在本机配置文件中把 `app.browser` 设为 `extension`，正常停止旧任务并重启 Web 服务，然后在控制台生成配对码。本项目当前使用 `web --port 8766`，控制台地址是 `http://127.0.0.1:8766`；省略端口参数时程序默认8765，扩展填写地址须一致。既有订单记录和保护保留。
4. 在日常浏览器中打开目标购物网页并正常登录。切回该购物标签页，从浏览器工具栏打开扩展，填入本机控制台地址和配对码，点击“连接当前标签页”。
5. 返回本机控制台检查登录状态、商品及购买条件，然后开始任务。验证码、短信、设备确认及最终付款仍由你操作。

配对码仅通过本机连接传递，等待配对期间只放在扩展的会话存储中，配对完成后删除；不会写入扩展文件或仓库。扩展未申请 `cookies` 权限；连接代码不读取或导出 Cookie，也不要求导出登录状态。`debugger` 本身具有较高权限，只应与自己信任的本机程序配对。

浏览器会显示调试连接提示。扩展只绑定一个明确选择的标签页；换平台或标签页前先断开连接。调试工具占用此页时，需要先关闭该页的开发者工具或结束其他调试连接。

## 停止与恢复

- 扩展里的“断开连接”立即停止连接并保留购物页面。任务记录、购物车状态和订单保护由本机程序保留。
- 网络断开、页面离开已选平台、扩展重载或服务工作者重启后，不会自动配对、重新开始或重放点击。先在控制台核对当前任务，再决定恢复。
- 既有待付款、未知提交或成功订单保护仍然有效。不要清空购物车、数据库或用户资料来启动演练。
- 开发演练默认不提交订单。正式提交需要本机程序明确启用；扩展弹窗本身没有提交或付款按钮。

扩展不会替浏览器创建/关闭购物标签页，不读取浏览器全部 Cookie，不重放 HTTP 请求。现有流程若必须打开另一个窗口、转往范围外域名或遇到尚未适配的页面，应停下人工核对。

## 开发检查与实际边界

在仓库根目录运行 `node --test extension/bridge.test.mjs`，检查配对、独立调试会话、域名约束、重复动作拒绝与断开清理。项目中的 `tests/test_extension_runtime.py` 使用临时 Chromium 和本地合成页面验证完整入口，不能算作真实商店验收。

平台真实页面进度与本轮实际执行结果以仓库的 `VALIDATION.md` 为准。扩展没有自己的商品选择器，也不会把未访问过的新品页面宣称为已支持。

Chrome 125 起才支持这里使用的调试子会话，见 [Chrome debugger 官方说明](https://developer.chrome.com/docs/extensions/reference/api/debugger#attach-to-related-targets)。
